## Implementation choices and departures

1. **Phone toolbar: three rows below560px container width, not two.** The original two-row English selectors produced407px scroll width inside362px. The smallest CSS change gives362/362px with all labels and targets visible. Centre/layer/scope order is retained; desktop and650px are unchanged. This uses the original brief's express permission for purpose-preserving technical corrections. Extra vertical room is the tradeoff.
2. **Core runtime properties, not template defaults.** Slot/lane geometry, drag bands/speed,160ms unit debounce,200ms grace, magnifier scale, mention/waveform/canvas design values live in core. The template reads them without numeric fallbacks. Film IDs/durations, crop data, intrinsic artwork and arithmetic remain application/content data.51 explicit numeric design reads have no missing core property; SF HTML has0 inline style attributes.
3. **Create-only no-dim override is important.** The merged shared dim selector is important; ordinary specificity did not beat it. A scoped opacity1!important preserves decisions14/20 without changing the shared UX engine or other samples. Effective ancestor opacity was measured, not only the leaf declaration.
4. **Persistent DOM and native input.** Monitor/info/secondary roots remain; script highlights toggle rather than replace the script. Chips use native noneditable spans/Backspace instead of an extra deletion handler. No backend generation is implied.
5. **Final magnifier repair.** Direct image review revealed a stale pointer coordinate: pointerleave hid the hero, but a later material-pick scroll reopened it outside the strip. The exact real-input probe reproduced this. Adding only `!strip.matches(':hover')` to updateHero fixes it. The probe and fresh full primary/A2/restoration reruns pass.
